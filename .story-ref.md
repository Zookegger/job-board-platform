## JBP-31: Employer Job DRAFT + Submit for Review

**Summary:** Là EMPLOYER, tôi muốn tạo và gửi duyệt tin tuyển dụng để chuẩn bị nội dung trước khi được công bố

**Status:** In Progress | **Priority:** Medium

### Acceptance Criteria

1. Create job post with default `DRAFT` status
2. Save and edit while in `DRAFT`
3. `DRAFT` not visible to candidates
4. Submit from `DRAFT` → `PENDING_APPROVAL` ("Gửi để xem xét")
5. Cannot edit after submitting until review completes
6. Job appears in admin review queue
7. Workflow: DRAFT → edit → submit → PENDING_APPROVAL → admin review → ACTIVE/REJECTED

## JBP-32: Employer Job Detail Info (Skills, Category, Salary, etc.)

**Summary:** Là EMPLOYER, tôi muốn khai báo thông tin chi tiết cho tin tuyển dụng để ứng viên dễ dàng tìm kiếm và đánh giá công việc

**Status:** In Progress | **Priority:** Medium

### Acceptance Criteria

1. Assign one or more skills to job
2. Select job category (ngành nghề)
3. Declare salary or salary range
4. Select work type (On-site, Hybrid, Remote)
5. Info saved with job
6. Visible to candidates in job detail
7. System can use these for search/filter

### Existing Server Implementation

| Requirement | Status | Details |
|-------------|--------|---------|
| Skills assignment | ✅ `JobRequest.skillIds` → `JobSkillServiceImpl.syncJobSkills` |
| Category selection | ✅ `JobRequest.categoryId` → resolved in `createJob`/`updateJob` |
| Salary min/max | ✅ `JobRequest.salaryMin`, `salaryMax`, `currency` — fully mapped |
| Location type | ✅ `JobRequest.locationTypes` (REMOTE, HYBRID, ONSITE) |
| Employment type | ✅ `JobRequest.employmentType` (FULL_TIME, PART_TIME, CONTRACT) |
| Experience level | ✅ `JobRequest.experienceLevel` |
| Saved with job | ✅ All fields persisted in `Job` entity |
| Visible in job detail | ⚠️ **Bug**: `JobResponse.skills` is always null — mapper ignores, service never populates |
| Public search/filter | ❌ **STUB** — `PublicJobController` all endpoints return placeholder strings |

### Known Issues

1. **`JobResponse.skills` always null** — `JobMapper.toResponse` has `@Mapping(target = "skills", ignore = true)` and no service method populates it after mapping.
2. **Slug not regenerated on title update** — slug set once at creation; title changes don't regenerate.
3. **Edit lock for PENDING_APPROVAL** — `updateJob` currently resets to DRAFT; AC says it should prevent editing entirely until review completes.

### Client Implementation

Same as JBP-31 — all client-side code is **STUB**. The form for creating/editing jobs with all the detailed fields (skills, category, salary, etc.) needs to be built.
